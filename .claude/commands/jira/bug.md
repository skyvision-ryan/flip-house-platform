处理缺陷：$ARGUMENTS

先用代码位置、可复现操作或测试确认事实，推测放在“疑似原因”。然后判断它属于哪一类，不一律开新票：

- **本次改动引入的回归** → 当前票必修，不另开票。
- **实现当前票目标不可缺少的修复** → 当前票做，记入变更记录并说明为什么不可缺。
- **独立的既有缺陷** → 在项目全部未完成票中按关键词查重，不假定 Jira 一定配置了 Bug 类型。命中已有票就补充证据，不建重复票；未命中时用项目实际支持的缺陷类型（若无 Bug 则建“任务”加 bug 标签），按 .claude/templates/ticket-bug.md 保持简洁，关联当前票，**不扩当前 PR**。
- **新需求** → 走 /jira finding 只提草稿。

只有确实阻止当前验收（技术依赖）才建 blocks，否则 relates to 后继续当前工作。
