把存量审计条目导入 JIRA。范围：$ARGUMENTS（留空 = 全部）

## 来源（权威顺序）
1. @docs/权威流程对照审计_2026-09-14.md §6（P0-01…P1-10，17 条）与 §9（五个批次 + 验收标准）
2. @docs/流程审计与开放问题_v3.md §7 改造清单、§8 开放问题（24 个）

## 结构
- §9 的每一批 → 一个 **Epic**（标题带批次号，描述放该批的验收标准）
- §6 的每一条 P0/P1 → 一个 **Story**，挂到对应 Epic
- §10 / §8 的业务待确认问题 → 一个 **Task**「业务确认」，作为相关 Story 的 `is blocked by`

## 每张 Story 必须带（不满足就不建）
- 审计原文引用（条目编号 + 文件行号）
- 代码位置（`文件:行号`）
- **当前真实状态**，三分类：已改 / 半改（写明哪半没改）/ 未动 —— 以本轮核实结论为准，不要照抄审计原文的「现状」，因为第一批修复之后部分条目已经变了
- 可验证的验收标准（命令 + 期望输出）
- 对应的 unittest 用例名（能落测试的）

## 顺序
按 §9 的批次顺序排，批内按 P0 → P1。**不要在这里写 rank**（Jira REST 写不了 rank）；建完告诉我建议的看板顺序，由我拖。

## 执行方式
**先只出草稿**（标题 + 类型 + 父子关系 + 优先级 + 验收标准摘要），一批一批给我看。我对哪一批点头，才建那一批。不要一次性全建。
