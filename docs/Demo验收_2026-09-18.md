# 周五 demo 验收脚本

目标日期：2026-09-18。状态：**待实现、待执行**。对应 [三个交付 Epic](本周开发Tickets_2026-09-15.md)。

## 准备

- 一个可重复访问的测试环境；记录提交、前后端版本、数据库类型、数据是否会重置；仅使用合成资料。
- 两套演示房，用于核对任务实例互不影响。主项目在一个实际演示阶段设 6–8 个任务。
- 负责人、执行者、同角色另一成员各一个测试账号；项目范围预先配置。至少一台电脑和一台 iPhone。
- 代表任务：一次性交付、需要审阅的交付、持续施工更新、等待外部回复、明确前置的任务、不适用任务；另保留 D/J 与 Final 规则的验证场景。
- instruction 写清目的、准备、步骤、证据与完成标准，示例依赖仅用于测试功能，不冒充已确认业务政策。

## 主流程

1. 负责人在电脑登录，查看项目任务，将一项工作派给执行者并设日期、说明与交付要求。
2. iPhone 上执行者登录，从“我的待办”进入该任务，看到相同房屋、日期和说明。
3. 执行者标记等待，填等待对象和原因。负责人刷新后能看到需协调事项。
4. 执行者恢复处理，通过拍照/相册/文件入口提交结果，任务进入待确认。
5. 负责人查看提交物并确认。双方看到一致状态，活动记录保留是谁在何时提交、确认。
6. 展示项目总览中的完成、等待和待确认事实，用已有记录组织一次进度汇报。
7. 改变主项目某任务说明或负责人，第二套项目保持原样。
8. 在 iPhone 将站点添加到主屏幕，退出窗口后从图标启动，验证登录、返回和任务访问。

## 反例必须成立

- 同角色另一成员不会因为角色相同而自动拥有该任务；不在授权项目范围时不能读、写或下载其中资料。
- 在正式模式伪造角色头不能改变身份或看到金额/密码。
- 持续施工上传一次照片只产生更新，整个施工仍未完成。
- 需要证据的任务缺文件时不能完成；待审阅任务不能通过普通状态修改绕过确认。
- 未满足明确前置时保持阻塞；审批节点不能用普通任务“不适用”跳过；最后一次 Final 检查未通过不能确认 Final。
- 上传失败不显示成功；重复点击不会生成重复完成或审批记录。
- 页面刷新或后端进程重启后，已保存任务/附件仍在当前测试存储中；这不替代下周 AWS 重新部署后的持久化验收。
