## T1 · 统一账号与 AWS 部署基础

**优先级：P0｜里程碑 A：09-16 demo 账号｜里程碑 B：09-23 AWS 部署｜依赖：先核对笔记本代码来源；云资源需要公司 AWS 输入。**

### 问题与结果

当前仓库与笔记本文档存在登录/阶段版本差异。需要先统一账号和业务用户标识支撑周五任务 demo，再将同一应用部署到可长期沿用的标准 AWS 基础，09-24 至 09-25 开始内部使用。

### 里程碑 A：本周代码

- 核对可取得的笔记本提交，复用登录/六段等已完成改动，保留当前修复；来源当天无法取得时补最小缺口并记录后续对账。
- 管理员建立/停用测试账号，配置角色/项目成员；真实 user_id 驱动分派、权限和日志；提供 T2 所需的可分派成员契约。
- 正式模式拒绝 X-Actor 自报身份；列表/详情/下载/更新和敏感字段统一授权。六段迁移保留 key、证据与审批历史。
- 认证适配层将本地 demo 或 Cognito 身份映射到同一个业务 user_id。外部身份用 issuer + subject 映射，邮箱和角色不是永久主键。
- 环境配置集中，正式空库不灌演示项目；保留 PostgreSQL/S3/认证提供方配置入口。同源 HTTPS 会话与写操作校验为部署准备。

### 里程碑 B：下周部署代码与环境

- 核心：**ECS/Fargate + RDS PostgreSQL + 私有 S3**；AWS 正式身份使用 **Cognito**，配套 **ECR、IAM、Secrets Manager、CloudWatch**。
- 保留一个前后端应用、同域名 /api；ALB/ACM 提供 HTTPS；CDK TypeScript 参数化管理基础设施。Amplify 在未来前端独立发布时接入。
- 实现 PostgreSQL 迁移、S3 适配、Cognito 身份验证/映射及项目权限；现有任务和审计 user_id 在切换认证后保持不变。
- ECR 固定版本发布，健康检查、日志/告警、回退脚本、数据库备份恢复及文件一致性验证；按实际网络/区域核算资源费用。
- 首期按小规格、少实例运行，明确维护窗口；后续在同一 AWS 体系内增加容量/高可用。

主要入口：用户/配置模块、`routers/common.py`、`main.py`、`db.py`、`dictionaries.py`、`frontend/src/App.tsx`、`api/client.ts`、`lib/actor.ts`；下周新增迁移、S3/认证适配及 `infra/`。具体文件名以统一基线为准。

### 验收标准

1. **A**：负责人和执行者使用独立会话登录/刷新/退出；停用后不能继续访问。未登录 401，伪造角色和越权请求被后端拒绝；受限响应无金额、密码或敏感文本旁路。
2. **A**：同角色两账号有不同 user_id，只能从授权项目成员中分派；六段映射保留旧交付和审批，正式空库无示例数据。
3. **A**：必要权限/会话测试与前端构建通过，记录来源提交和身份提供方；T2/T3 可据此联调，无需等到云里程碑完成。
4. **B**：AWS 环境通过 Cognito 实际登录，后端验证 token 并落实业务权限；demo 认证关闭，人员切换后任务和活动历史仍属于原业务用户。
5. **B**：替换 task/重新部署后数据和附件保留；恢复数据库到新实例并读到带附件任务；应用可回退到上一个兼容版本。
6. **B**：基础设施可从 CDK 参数重建、配置和密钥不入前端/Git；HTTPS、网络、日志/告警、费用核算及 iPhone 会话联调有记录。09-24 至 09-25 用 2–3 套房开始内部试用。

### 范围边界

完整方案见 [AWS 统一部署方案](AWS内部部署方案.md)。不重写业务为全 serverless、不拆微服务、不实现开放自助注册或完整公司 SSO；本次文档任务尚未创建云资源。三张 ticket 中只有 T1 分为本周身份和下周部署两个里程碑，日期分别验收。

## T2 · 将阶段清单变成可分派、可验证完成的项目任务

**优先级：P0｜目标完成：09-17｜依赖：T1 的 user_id、成员和权限契约。**

### 问题与结果

当前清单主要表示是否打勾，不能独立安排每套房的负责人、日期和说明，持续工作也可能被一次上传误报完成。建立最小 Task 实例，使“谁做、怎么做、交什么、怎样完成”可以按项目管理。

### 代码范围

- 从阶段模板生成项目任务副本：标题、stage_key、template_key/版本、默认角色、assignee_user_id、通用说明与项目补充、交付要求、完成规则、到期日。
- 支持新建/修改/分派任务和改期原因；未开始、进行中、等待、待确认、完成、不适用。等待记录在等谁/什么及原因；不适用仅由有权人员设置并留理由，不能跳过关键节点。
- 区分一次性交付、持续工作和审批节点；需要审阅的交付进入待确认。复用已有文件、检查和采购记录，保留 D/J 和 Final 规则。
- 最小显式前置支持“前置未满足 → 显示阻塞并拒绝不允许的动作”；拒绝自依赖/循环。不做关键路径、自动日期平移或全量流程引擎。
- 所有修改写入活动记录，包含实际 user_id、时间、变更前后值与原因；重复提交不重复完成/重复确认。
- 提供最小网页端任务安排入口，并让个人待办与项目总览读取同一任务状态。旧步骤通过适配/映射接入，不能两边独立写出互相矛盾的状态。
- 数据迁移可重复运行，不能重复生成任务或丢失原始证据；演示两套项目相互独立。

主要入口：`backend/app/models.py`、`schemas.py`、`steps.py`、`routers/steps.py`、`routers/dashboard.py`、文件关联、前端 API 与最小任务管理组件。

### 验收标准

1. 两套项目各有自己的任务副本；改一个项目的说明、负责人或日期，不影响另一项目或模板。
2. 指派到具体账号后，只进入该账号的个人待办；同角色另一成员不会成为共同负责人。
3. 上传一张施工照片只新增更新；保险单只满足保险对应要求；缺交付物/待审阅任务不能被普通完成操作绕过。
4. 等待、改期、不适用有原因和留痕；明确前置未完成时显示阻塞；正常并行任务仍可推进。
5. 提交、确认或重新打开后，待办、总览和活动记录一致；关键节点不能被普通状态 PATCH 绕过。
6. 迁移、实例隔离、权限、完成规则和重复提交测试通过，前端构建通过；保留现有 Final 与金额规则回归。

### 范围边界

周五只要求主演示阶段 6–8 个任务具有完整说明与真实交接，六段保留基础模板。任意层级子任务、模板编辑器、批量排程和完整业务依赖建模留到实际试用后。

## T3 · 跑通 iPhone 任务执行与负责人验收

**优先级：P0｜目标完成：09-18 周五｜依赖：T1 登录及 T2 任务/动作接口。**

### 问题与结果

团队以 iPhone 为主。执行者需要从手机直接了解任务、提交材料和反馈等待，负责人在另一台设备确认后看到项目变化。用响应式 React/Cloudscape 网页完成这条交接，并支持添加到主屏幕。

### 代码范围

- 手机首页突出“我的待办”，按项目/状态筛选，明确显示待我处理、等待、待确认与逾期；负责人能查看待确认和需协调的事项。
- 任务详情展示房屋、负责人、日期、通用 instruction、项目补充、交付要求和活动记录；可更新状态、反馈等待原因、上传照片/文件、提交审阅。
- 负责人审阅提交物、确认或退回并写原因，任务与项目总览随服务器结果更新；刷新/再次进入也保持一致。
- 适配 iPhone Safari 与主屏幕独立窗口：manifest、图标、启动地址、viewport/safe area、软键盘、返回导航和登录保持。首版按联网运行，避免缓存登录响应和敏感 API 数据。
- 上传支持从相册/文件选择，提供拍照入口；验证实际返回的图片格式、大小限制和失败提示，不强行声称所有 iPhone 照片格式都能预览。未成功提交保留可恢复的输入，重试不重复创建记录。
- 复用更新记录展示“本周完成/等待/待决策”的事实，供负责人汇报；不在这张票接 LLM 或建立新报表引擎。

主要入口：`frontend/src/pages/MyTodo.tsx`、`components/MyTodoTable.tsx`、任务详情、`UploadForm.tsx`、`pages/project/OverviewTab.tsx`、`App.tsx`、`index.html` 及 PWA 图标/manifest。

### 验收标准

1. 375px、390px、430px 宽度下可完成核心操作，无页面级横向滚动；键盘/底部安全区不遮挡提交按钮。
2. 至少一台实际 iPhone 验证 Safari 和主屏幕启动，记录型号/iOS；仅桌面模拟不等同真实 iPhone 通过。若暂时没有设备，如实标注待验证。
3. 负责人分派 → iPhone 查看说明 → 标等待并说明原因 → 恢复 → 拍照/选文件 → 提交 → 负责人确认，整条链路可演示；状态均来自后端。
4. 冷启动、刷新、返回、退出后重登能正确恢复或清理身份；网络/上传失败有清晰提示且不能误显示提交成功。
5. 施工进度照片不完成整个施工，缺证据不能完成受约束任务；受限账号不能访问其他项目或受限资料。
6. 按 [demo 脚本](Demo验收_2026-09-18.md) 完成，附测试版本/环境、录屏或操作记录；前端构建与相关后端回归通过。

### 范围边界

首版是联网网页应用，支持主屏幕入口；原生 Swift、App Store、TestFlight、离线队列、后台上传与系统推送不作为本周交付。照片失败重试不要求跨应用关闭后自动后台续传。
