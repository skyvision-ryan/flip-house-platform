## 当前风险与归属

| 风险 | 代码事实 | 处理位置 |
|---|---|---|
| 项目授权缺失 | 当前多数 API 仍按角色判断，未建立用户—项目成员关系 | KAN-21 |
| 会话撤销不完整 | 停用用户会拒绝请求；修改密码不会立即使旧签名 Cookie 失效 | KAN-21 验收时处理或明确拆单 |
| 正式配置可误用 | `DEMO_MODE=0` 且未设 `SECRET_KEY` 时只警告；随机密钥会导致重启后全部退出 | KAN-21 / KAN-26 |
| S3 尚未实现 | `STORAGE`、`S3_BUCKET` 只是配置字段 | KAN-23 |
| 数据迁移不足 | 当前用建表和补列兼容，没有正式迁移版本链 | KAN-22 |
| 金额口径不统一 | dashboard 的预计利润采用简化公式，与 analysis 的融资/持有成本口径不同 | 核对现有 Jira 覆盖后再决定是否拆单 |
| 旧步骤与新任务并存风险 | 新任务若另存一套可修改状态，会与清单/总览矛盾 | KAN-27–30 必须使用同源状态 |
| 本地守卫不是强制门 | Claude hooks 不覆盖其他工具 | 本次新增 CI；合入后由 GitHub 执行后端、守卫和前端检查 |

## 演示和内部使用边界

- `DEMO_MODE=1` 下未登录会按演示负责人处理，可能读取敏感演示字段。只允许合成数据。
- 内部试用必须关闭 demo/seed，固定密钥，使用真实身份与项目授权，并完成 PostgreSQL/S3、部署和恢复验收。
- Render 演示站跟踪 main；合并可能触发部署，但线上健康和提交号需要实际检查。
- AWS、iPhone 与 Jira 状态只按真实记录声明；配置文件、建单或合并本身不等于完成。
