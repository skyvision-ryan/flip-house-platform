# 产品方向与执行原则

更新：2026-09-15。依据：用户 9/14 项目全景整理、9/15 Jira Mobile/FDE 讨论，以及“周五 demo、下周 AWS 内部使用”的最新要求。

## 1. 产品是什么

为翻房公司提供围绕每套房运转的协作与数据系统：明确谁该做什么、怎样做、交什么、在等谁、由谁确认；让执行记录关联项目、文件、预算和实际支出。

近期验证团队是否能依靠它完成实际任务交接。长期发展为可复用的翻房 SaaS，并逐步扩展成了解公司流程、历史成本和决策依据的房产 AI 助手。

FDE 的工作方式：进入真实业务 → 写出可执行任务与说明 → 带团队使用 → 记录例外和反馈 → 调整项目任务 → 将共性经验更新到模板。合理的项目例外允许存在，不能为了通用模板抹掉事实。

## 2. 三个产品方向如何连接

| 方向 | 主要使用场景 | 本轮取舍 |
|---|---|---|
| 移动端执行 | 我的任务、操作说明、照片/文件、状态、卡点、待确认 | 本周核心；iPhone 为主，响应式网页支持 Safari 和添加到主屏幕 |
| 网页端管理与数据 | 项目总览、任务安排、算账、预算与实际、文件和来源 | 复用已有页面，补最小任务管理入口；保持数据与执行关联 |
| 房产 AI 助手 | 查事实、解释进展、整理汇报、找说明、预填和辅助办理 | 先有可靠数据与状态；本周保留规则助手，真实 LLM 不作为 demo 验收门槛 |

借鉴 Jira 的任务组织、个人待办、负责人、状态、说明和活动记录。前台用翻房团队熟悉的语言。手机窄屏优先可操作列表与详情，横向多列看板只在适合的宽度下作为可选视图。

保持 Cloudscape 组件体系。沿用 9/14 整理记录的界面偏好：阶段使用卡片/列表，不以新增进度条、轨道图或甘特图作为本轮改版方向。既有界面差异在相关 ticket 中逐步处理。

首版联网运行；iPhone 重点验证相册/拍照/文件上传、键盘、底部安全区、登录保持和主屏幕启动。原生 App、离线同步与系统推送后续按需求安排。用户要求首次内部上线兼顾后续全面采用 AWS，架构统一为 [ECS/Fargate + RDS PostgreSQL + S3 + Cognito](AWS内部部署方案.md)，首期同源提供前后端；IAM、ECR、密钥、日志和基础设施代码沿用标准 AWS 体系。

## 3. 项目、模板与任务

- 一套房对应一个 Project。
- 目标模板六段：预买房 → 买房与过户 → 装修 → 预上市 → 卖房上市 → 售出收尾。五段旧版的映射在迁移中保留；不是直接改数组序号。
- Task 模板预设默认角色、操作说明、交付要求和完成规则；Task 实例保存具体账号、项目补充说明、到期日、状态和实际结果。
- 新项目生成自己的副本，项目内改任务不改变其他项目；模板更新默认只作用于以后新建的项目。
- 仅需要独立分派、独立期限或独立验收的事项拆为子任务；其余操作步骤放在说明的检查清单中。本周不要求实现任意层级嵌套。
- 每个任务有一个主要负责人，可记录协作者和等待方；D/J 审批人另行保存，不能用“一名负责人”取代双人确认。
- 角色管权限，账号接任务。同角色的两个人不应自动成为同一任务的负责人。

任务说明至少回答：目的、准备材料、执行步骤、参考资料、交付物、怎样算完成、遇到例外如何反馈。通用说明与本项目补充分开，先用普通文本和简单清单即可。

## 4. 状态、证据与完成

目标状态：未开始、进行中、等待、待确认、完成、不适用。任务状态独立于业务阶段；阻塞由明确前置未满足派生，逾期由到期日与未结束状态计算。

等待至少记录对象/事项及原因，可加预计回复日期；改期保留原日期和原因；不适用保留理由与操作人。哪些关键节点允许豁免仍是业务问题，普通任务的“不适用”能力不能绕过关键节点。

| 任务性质 | 示例 | 完成规则 |
|---|---|---|
| 一次性交付 | 提交指定版本的申请回执 | 符合该任务要求的交付物到齐；需要审阅的进入待确认 |
| 持续工作 | 施工、采购、permit 跟进 | 照片和记录是更新；明确范围的工作包交付并确认后才结束 |
| 审批或里程碑 | 可以开工、Final、交割 | 满足适用的事实前提，再由指定人确认；保留 D+J 双确认及最后一次 Final 检查通过规则 |

不能用“上传了一张施工照片”完成整个施工，也不能用保险单完成贷款。任务拆分与完成规则必须能表达这一点。

任务、个人待办、项目总览、更新记录和助手引用同一套业务状态。已有步骤证据通过稳定 key 关联到任务，迁移时保留文件、时间、审批人和手工确认来源；无法确认的历史记为待核验，不伪造已完成结果。

仅实施已经明确的依赖，允许并行工作。许可范围、贷款方、付款和收尾规则的开放问题逐项保留，不将所有流程图顺序推断为强制依赖。

## 5. 人员、权限与协作

保留决策、统筹、执行、外部四级权限意图及现有金额边界。首轮用管理员建独立账号，AWS 正式环境采用 Cognito 认证；应用维护稳定 user_id、角色和项目授权。Demo 可复用本地认证适配，不能将它误称为 Cognito。邮箱邀请、公司 SSO、完整承包商门户排在后续。

正式模式由后端验证登录会话；不能相信客户端自报身份。授权同时考虑角色、项目范围和动作；列表、搜索、下载、任务详情、更新记录与助手都遵守相同边界。

账号/角色和真实人员的对应是待落实配置，不能把未确认代号擅自映射为真实姓名。任务记录实际 user_id，角色快照仅用于解释当时权限和分工。

## 6. 数据与未来 SaaS

继续积累：房产字段来源、估算版本、预算与支出、文件及版本、任务耗时、延期/变更原因、检查结果、采购到货、最终成交与复盘。

数据产品的价值通过实际使用验证：来源能否追溯、资料能否完整交接、估算和实际能否对照、其他团队能否复用模板。当前界面详尽不代表真实数据源或商业化条件已经完成。

长期方向依次包括：历史项目回灌估算；Lark 导入与提醒；获授权的数据接口；成本与工期对照；供应商和承包商表现；模板复用；经外部试点验证后再做多组织隔离、租户配置、收费与商业 onboarding。

本周的数据工作以支持任务交接为边界；不新增大批数据看板、不做财务系统或 MLS 替代品。

## 7. AI 从问答到办理

| 阶段 | 能力 | 依赖与验收 |
|---|---|---|
| 当前 | 规则洞察与页面链接 | 明确标注规则生成；身份切换/退出后清理或重取上下文 |
| 首个 LLM 试点 | 负责人/J 查进展、整理汇报、找任务说明，答案带记录链接 | 真实数据、权限工具与可核对的问题集；读取和摘要不必等完整排程引擎 |
| 辅助执行 | 查任务下一步，生成说明或预填，展示待确认变更 | 已有任务实例、稳定动作接口与完成规则；确认后后端再次校验，记录真实操作人和助手来源 |
| 主动协助 | 到期、阻塞、待决策提醒及定时摘要 | 日期和等待信息可靠；通知渠道、接收人和去重策略明确 |
| 房产决策助手 | 结合公司历史与获授权外部资料解释买入、装修、成本与卖出方案 | 真实来源、确定性计算、适用范围与复盘；再向更广泛房产场景扩展 |

AI 通过服务端业务工具获取有权限的数据；计算金额继续复用确定性代码。查询不到的信息应明确缺失，不能填造事实。解释超支/延期原因需要对应变更或现场记录，仅有总金额/日期时只能陈述偏差。

知识范围同时包含结构化项目数据和文本资料：任务说明、流程规范、相关文件、变更理由。先按项目/任务取相关资料片段；当资料规模和检索需求出现后再选择检索方案，不预设必须有向量数据库，也不永久排除文本检索。

模型只提出动作；服务端执行时验证当前用户、项目、允许字段与最新前提。审计中将操作者 user_id 与 assistant 来源分开，不篡改身份字符串代替真实用户。保持规则助手回退，记录问题、引用、调用与实际用量；模型/供应商、预算、数据处理边界在实际接入时核实，不沿用旧文档的粗估价格或 SDK 断言。

## 8. 怎样衡量近期价值

周五：两台设备、两个实际测试账号、同一项目，完成分派 → 阅读说明 → 更新/等待 → 提交 → 确认 → 总览更新；第三个受限账号验证访问边界。

内部试用：2–3 套在建房，观察任务是否由执行者直接更新、交付物能否追溯、负责人能否直接组织汇报，以及大家仍需离开系统追问什么。用这些反馈决定下一轮投入。

交付日期、代码任务、AWS 方案和发布条件统一维护在 [ROADMAP](../ROADMAP.md)。


## 9. 仍需业务确认

这些问题来自已退役的旧审计，尚未得到明确答案。只在具体 ticket 依赖它时确认，不阻塞无关开发，也不能由 AI 擅自推断。

- **关键门**：收到 offer 与接受 offer 的节点、哪些门必须 D/J 双确认、负责人能否代批及例外政策。
- **融资与付款**：是否存在第二贷款方、measure/payoff 的必要材料、付款申请与审批人、预算冻结和变更规则。
- **售出收尾**：签署、交割、到账、record 与关闭服务分别怎样判定完成。
- **Permit 与检查**：survey/measure 的含义、内部与市政检查分类、谁可以办理 permit、哪些施工必须等 permit。
- **采购**：不同检查前必须到场的材料、规格/数量/交期、付款人与审批里程碑。
- **职责**：尽调、贷款、园艺、深度清洁、escrow 等新增事项由谁负责，哪些外部参与者需要系统账号。
- **金额口径**：as-is、ARV、定价、利润包含哪些成本，估算何时锁定，实际与预算如何对照。
- **资料边界**：PM、贷款方、承包商等可读写的文件、金额和凭证范围；真实人员代号映射须由负责人确认。
