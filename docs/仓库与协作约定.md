## AI 开工前的检查

运行 `python3 scripts/check_workspace.py`。它只读 Git 状态，不切分支、不覆盖文件、不联网，也不替你拉取最新代码。需要新远端状态时先 `git fetch origin`，涉及笔记本来源时再 `git fetch upstream`。

检查并报告：当前绝对目录、分支、HEAD、origin/upstream、未提交文件、相对 origin/main 的差异以及是否正在合并。早先的状态记录不能代替这次检查。

本机两个克隆的 Git 配置统一采用：默认推送到 origin；普通 push 只推当前有明确同名跟踪分支的工作；普通 pull 只接受快进。这里没有配置自动合并或强制覆盖。

## 协作规则

1. 一个工作目录同时只由一个助手修改。Claude 正在 Desktop 处理 KAN-20 时，其他助手不要替它切分支、重置文件或处理同一组冲突。
2. 新任务从更新后的正式基线创建带票号的分支。并行开发使用独立 worktree；不要再建立来源不明的同名克隆。Codex 分支采用 `codex/KAN-编号-说明`，Claude 可沿用 `KAN-编号-说明`。
3. 每次交付：相关改动与必要测试 → 带票号提交 → 推送 origin 对应分支 → PR → 验收后合入 main。分支可见不代表已合入，也不代表已部署。
4. 切换目录或让另一位助手接手时，必须交接“目录、分支、提交、未提交内容、验证结果、下一步”。不要靠聊天摘要猜版本。
5. 正式基线更新后，干净的 main 用 `git pull --ff-only` 更新；有未提交内容或合并中的工作区先由当前实现者收尾，不执行强制同步。
6. 项目入口和排期统一读取 [AGENTS.md](../AGENTS.md)、[ROADMAP.md](../ROADMAP.md)、[Jira 执行清单](Jira执行清单_2026-09-15.md)。不要复制成相互独立的新版计划。
