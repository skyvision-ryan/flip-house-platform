## 日常协作

1. **同一时间只有一个助手修改这份工作区；另一位只检查。** 用户交接后再换人，不同时改代码、切分支或合并。
2. 干净的 main 用 `git pull --ff-only` 更新；有改动或合并未完成时先保留并交接，不执行强制同步。
3. 从最新 main 开带票号的分支。Codex 用 `codex/KAN-编号-说明`，Claude 可用 `KAN-编号-说明`。
4. 每次交付包含代码、必要验证、带票号提交、推送 origin、PR 和验收。正式发布情况另行核实；推送不等于合并，合并不等于部署成功。
5. 默认保持轮流开发。只有用户另行安排并行任务时，才创建明确命名的独立 worktree，不再随意复制同名项目文件夹。
6. 交接至少写明分支、提交、未提交内容、验证结果及下一步。产品方向和排期共同读取 [AGENTS.md](../AGENTS.md)、[ROADMAP.md](../ROADMAP.md) 与 [Jira 执行清单](Jira执行清单_2026-09-15.md)。

Git 本机配置为默认推送 origin、push.default=simple、pull.ff=only。涉及 gh 命令时显式写 `--repo skyvision-ryan/flip-house-platform`，避免选到 upstream。
