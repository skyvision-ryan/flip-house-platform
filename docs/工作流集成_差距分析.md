## 2. 缺的

按文档章节，缺口从大到小：

1. **任务实例**（§16、§28）：任务只存在于配置里，每套房不能增删任务、改负责人、设到期日、标不适用。`project_steps` 只记勾。
2. **Workstream 维度**（§5、§16）：装修段是一条平列表（采购 / 进度 / 检查 / agent / final），没有 permit / 设计 / 承包商 / 采购 / 施工 / 检查 / 付款 / 水电 / 园林 / City Final 十条并行线。
3. **依赖与阻塞**（§18–20）：没有 `task_dependencies`，没有 `blockers` 表；唯一的硬前置是 final 门要验收通过。
4. **任务状态机**（§10、§31）：没有 NOT_STARTED / READY / IN_PROGRESS / WAITING / BLOCKED / REVIEW / DONE，无法区分"在等"和"卡住"。
5. **Permit 循环**（§6）：permit 只有两个文件类型（申请回执、核发文件），没有提交 / 审核 / 补件 / 重交 / 批准的多轮状态。
6. **承包商与付款**（§8、§11）：没有承包商对象、合同、付款节点；`expenses` 是支出流水不是付款审批；"完成 ≠ 可付款"没有落地。
7. **施工工序里程碑**（§10）：没有拆除 / 框架 / 水电 / 保温 / 干墙 / 精装的工序清单，只有进度照片。
8. **预买房独立段与 Gate A 审批状态**（§3）：尽调三项（死亡记录 / 无证改建 / 违规记录）只是风险文本；分析器有数但没有 DRAFT / UNDER_REVIEW / APPROVED / REJECTED。
9. **Closeout 段**（§15）：关水电、退保险有；成本对账、已实现利润、归档没有作为步骤。
10. **到期驱动的条件任务**（§14C）：保险到期有提醒；贷款到期（loan maturity）没有字段。
11. **用户与分派**（§17 assigneeId）：只有角色代号。
12. **通知**（§27）：无。
13. **Listing readiness %、里程碑权重、critical path**（§13、§21、§22）：无。

## 3. 目前建模不对的地方

1. **模板和实例混在一起**。完成状态按模板 `key` 存，改模板就改了所有历史项目的解释；不能按房定制。这是所有缺口的根。
2. **两套阶段模型并存**。`projects.stage/substage`（lead / active / portfolio + 子段）驱动状态规则、筛选、漏斗；五段清单派生 `current_stage` 驱动总览与待办。两者不同步，手改 `stage=portfolio` 就能让房子"完成"。
3. **证据 = 完成**。文件存在即 done，没有"已交 / 已审 / 已批"三态；"手工确认（无证据）"是补丁。
4. **门放在段内列表里**，第②段的开水电、第⑤段的卖房文件在门后；当前段只由"第一道门"推进，第⑤段第二道门（交割）不参与阶段判定。文档的模型是门在段之间、里程碑在线内。
5. **Permit / 设计 / 承包商被建成文件类型**，没有生命周期。
6. **采购的"需用节点"不是依赖**。`procurement:critical` 硬编码只看"水电检查前"那组；缺货不会自动挡住任何施工任务。
7. **检查记录不挂工序**，failed 只影响 final 门；付款与检查无关。
8. **阻塞在前端算**（`insights.ts`），按身份过滤，刷新即失，无人负责、无解决记录。
9. **日期只有项目级五个**，`construction_end` 既当计划完工又当实际完工；任务无到期日，所以"逾期"只能在项目级判断。
10. **负责人写死在模板 owners 里**，同一代号（J）在所有房都是同一个人，不能按房换人。

## 5. 让流程"自然落进来"的阻碍

1. 没有任务实例表 → 依赖、阻塞、到期、负责人、定制都没有落点。
2. 没有 workstream 字段 → 装修段没法展示并行线，UI 只能平铺。
3. 只有"done"一个状态 → 等待 / 阻塞 / 待审无处表达。
4. 阶段双轨 → 进度、健康、筛选各说各话。
5. 身份是自报的代号 → 分派和审批只是演示级。
6. SQLite 无迁移工具 → 改表结构要靠加列；新表可以，改列难。

## 6. 最小的架构改动（能不动的都不动）

只加三张表、一个字段、一次迁移：

1. **`project_tasks`**（任务实例）：`project_id, key, template_key, stage_key, workstream, title, kind(task|milestone|gate), owners(json), assignee, status, due_date, evidence_rule, deliverable(json), confirm(json), sort_order, not_applicable, custom`。
   - 建项目时从模板实例化；老项目一次性迁移（模板 key → 实例，`project_steps` 里的勾按 key 对上）。
   - `compute_steps` 改为读实例，证据规则不变；`project_steps` 继续存勾 / 确认。
   - 这一张表同时解决：按房增删改任务、改负责人、到期日、不适用、workstream 分组。
2. **`task_dependencies`**（`task_id, depends_on_task_id`，只做 FINISH_TO_START）：模板里给默认依赖（permit 申请 ← 设计定稿 + 量尺；开工门 ← permit 核发；staging ← final；签署 ← 文件包 + 披露；关水电 ← 交割），实例化时复制。`ready` 状态由此派生。
3. **`blockers`**（`project_id, task_id, category, title, severity, owner, status, expected_resolution, resolved_at, source(auto|manual)`）：现有 `insights.ts` 里那几条规则搬到后端生成 `source=auto` 的阻塞；人工可加；工作台"需要关注"和项目页"阻塞"读这张表。
4. **任务状态字段**：`NOT_STARTED / READY / IN_PROGRESS / WAITING / BLOCKED / REVIEW / DONE / NA`。DONE 仍由证据或确认自动写；WAITING / BLOCKED 由阻塞表派生；READY 由依赖派生。
5. **阶段单轨**：`projects.stage/substage` 改为派生值（写库仅为兼容旧筛选），编辑弹窗里只读。
6. 模板从 5 段 29 项改为 **6 段 + workstream 标签**（对齐团队定稿 35 项与本文档六段），旧 key 保留映射。

不做：用户表、通知、critical path、里程碑权重、通用工作流引擎。

## 7. 分阶段计划

| 阶段 | 做什么 | 交付 | 验收 |
|---|---|---|---|
| **P1 归一** | 模板改六段 + workstream 标签；旧 key 映射表；`projects.stage` 改派生；`current_stage` 判定支持一段多门 | 只改配置与派生逻辑，界面不变 | 十套示例房阶段不变；已售仍"全部完成" |
| **P2 实例化** | `project_tasks` 表 + 建项目实例化 + 老项目迁移；`compute_steps` 读实例；总览 B 面板按 workstream 分组；任务行可改负责人 / 到期日 / 不适用 / 新增自定义任务 | 一套房能定制清单 | 加一条自定义任务、改负责人、标不适用后总览与待办都对 |
| **P3 依赖与阻塞** | `task_dependencies`、`blockers`；READY / BLOCKED 派生；自动阻塞四条规则搬后端；阻塞面板（项目页 + 工作台）带负责人与解决 | 能回答"卡在哪、谁负责" | 缺货 → 施工任务 BLOCKED；permit 补件 → 开工门 BLOCKED；解决后自动恢复 |
| **P4 下一步引擎** | 后端 `next_actions`：未完成 ∧ 依赖满足 ∧ 可操作，按逾期 / 阻塞解决 / 门 / 到期排序；替换 `next_up`、`my_todo` 数据源 | 工作台"轮到谁"和待办变准 | 每套房前三条与人工判断一致 |
| **P5 装修专项** | `permits` 表（多轮状态）；施工工序里程碑进模板；检查记录挂里程碑、`kind`；采购加 vendor / 预算 / 交期并生成阻塞；付款表 + 可付款判定（检查通过 + 审批） | 装修段真正并行可控 | 检查 failed → 里程碑 REWORK，付款不可用；复检 passed → 可付款 |
| **P6 高管视图** | 进度按里程碑；健康含阻塞；listing readiness %；每日更新自动摘要（今日完成 / 阻塞 / 下一步） | 30 秒回答文档 §34 的十个问题 | 用 N Holmes 和 Parkville 两套房走一遍 |

P1–P2 可以在现有界面上完成而不改布局；P3 起工作台"需要关注"换数据源；P5 才动装修相关页面。

## 8. 建议先改的文件

1. `backend/app/dictionaries.py` — 模板改六段、加 `workstream`、加默认依赖、旧 key 映射。
2. `backend/app/models.py` — 加 `ProjectTask`、`TaskDependency`、`Blocker`。
3. `backend/app/steps.py` — `compute_steps` 改读实例，加 READY / BLOCKED 派生，一段多门。
4. `backend/app/routers/projects.py` — 建项目时实例化任务；PATCH 不再直接写 stage。
5. `backend/app/routers/steps.py` — 勾 / 确认按任务实例 id；加任务增删改接口。
6. `backend/app/seed.py` — 老项目迁移函数 + 示例数据走实例。
7. `frontend/src/api/client.ts` — 任务、依赖、阻塞类型。
8. `frontend/src/components/StepsPanel.tsx` — 面板按 workstream 分组，行显示状态 / 负责人 / 到期。
9. `frontend/src/lib/insights.ts` — 阻塞规则迁出到后端后只剩展示。
10. `frontend/src/pages/Dashboard.tsx` — "需要关注"、"待我确认的门"、"我的待办"换成 blockers / next_actions。

顺序是 1 → 2 → 3 → 6（先让后端自洽、示例数据跑通）→ 4、5 → 7 → 8 → 9、10。
