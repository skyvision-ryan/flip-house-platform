# Flip House 新项目启动检查

产出一份可直接行动的启动检查，并严格区分已知事实、待补资料和待业务决定。

## 执行边界

1. 先读取 `../../../docs/产品方向与执行原则.md` 里的新建项目、人员权限与近期使用路径。如需核对现有能力，再读 `../../../docs/当前实现与版本核验.md`。
2. 不从会议转写、文件名或字母代号猜真实人名。未确认的值标为「待确认」，不为了通过检查而补造。
3. 项目存在与阶段可见，不等于金额、凭证、贷款、保险或合作商资料可见。创建或读取工具必须遵守当前用户、项目范围与动作权限。
4. 如用户只要检查，不创建或改动项目。如用户明确要创建，只在必填资料齐全、身份与权限已验证且有可用的受控工具时执行；否则返回精确缺口。
5. 不把合成数据、演示账号或 seed 内容带入真实项目。不把业主、凭证原件或登录秘密写入代码库。

## 启动检查

至少核对：

- 项目识别：项目名称与房产地址。
- 基础业务资料：ARV／装修后预计售价、预计项目周期、房屋基本情况、上一次交易时间与金额、土地用途／Zoning。
- 参与人：负责统筹、主要执行职责与首批项目成员；真实姓名未确认时保留 D、J、K 等现有代号。
- 使用起点：项目处于哪个阶段，当前事实是什么，对应职责的人第一件要做什么。
- 环境：真实试用环境不灌演示项目，并能区分「项目已创建」「用户有权看」和「用户有权修改」。

## 输出

使用三类结果：

- **已就绪**：可直接用于创建或启动的已核对事实。
- **待补资料**：谁可以补、缺什么、是否阻塞当前动作。
- **待业务决定**：只列会改变权限、流程或项目起点的问题，并标明应由 Jesse 或 David 中的谁确认；无依据时不猜指定人。

结尾给出一个最小下一步。不用“资料还不完美”阻塞所有工作；只有缺口会使当前动作不安全或产生错误事实时才标为阻塞。
